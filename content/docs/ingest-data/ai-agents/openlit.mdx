[OpenLIT](https://openlit.io/) is an OpenTelemetry-native observability SDK for AI applications. It automatically instruments model-provider SDKs and AI frameworks, then emits GenAI traces and metrics with model, token, cost, latency, streaming, and error attributes.

This guide routes OpenLIT telemetry through the OpenTelemetry Collector. The Collector keeps the Parseable API key out of application code, batches telemetry, and sends each signal to its own Parseable dataset.

```text
AI application using OpenLIT
  |
  | OTLP/HTTP traces and metrics
  v
OpenTelemetry Collector
  |
  +--> openlit-traces   traces dataset in Parseable
  +--> openlit-metrics  metrics dataset in Parseable
```

## Prerequisites

Before you start, keep these ready:

- A running Parseable instance
- A Parseable API key with ingest access
- Python 3.9 or newer
- An OpenTelemetry Collector Contrib binary or container
- A model-provider API key, such as `OPENAI_API_KEY`

## Set up OpenLIT with Parseable

<Steps>
<Step>

### Configure the OpenTelemetry Collector

Create `otel-collector-config.yaml`:

```yaml
receivers:
  otlp:
    protocols:
      http:
        endpoint: 0.0.0.0:4318

processors:
  batch:
    timeout: 5s

exporters:
  otlphttp/parseable_traces:
    endpoint: "${env:PARSEABLE_URL}"
    encoding: json
    headers:
      X-API-Key: "${env:PARSEABLE_API_KEY}"
      X-P-Stream: openlit-traces
      X-P-Log-Source: otel-traces

  otlphttp/parseable_metrics:
    endpoint: "${env:PARSEABLE_URL}"
    encoding: json
    headers:
      X-API-Key: "${env:PARSEABLE_API_KEY}"
      X-P-Stream: openlit-metrics
      X-P-Log-Source: otel-metrics

service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [batch]
      exporters: [otlphttp/parseable_traces]

    metrics:
      receivers: [otlp]
      processors: [batch]
      exporters: [otlphttp/parseable_metrics]
```

Set the Parseable endpoint and API key, then start the Collector:

```bash
export PARSEABLE_URL="https://<parseable-host>:8000"
export PARSEABLE_API_KEY="<parseable-api-key>"

otelcol-contrib --config otel-collector-config.yaml
```

Use the Parseable base URL for `PARSEABLE_URL`. The `otlphttp` exporter appends `/v1/traces` or `/v1/metrics` for the corresponding pipeline.

<Callout type="info">
You do not need to create the datasets manually. Parseable creates `openlit-traces` and `openlit-metrics` when the Collector sends the first OTLP payload with the configured `X-P-Stream` and `X-P-Log-Source` headers.
</Callout>

</Step>
<Step>

### Instrument the application

Install OpenLIT and your model-provider SDK. This example uses OpenAI directly with your own provider key:

```bash
pip install openlit openai
```

Initialize OpenLIT before importing the provider SDK:

```python
import os

import openlit

openlit.init(
    otlp_endpoint="http://localhost:4318",
    service_name="customer-support-agent",
    environment="production",
    capture_message_content=False,
)

# Import after openlit.init() so OpenLIT can instrument the client.
from openai import OpenAI

client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

response = client.responses.create(
    model="gpt-4o-mini",
    input="Explain AI observability in one short sentence.",
    max_output_tokens=50,
)

print(response.output_text)
```

`capture_message_content=False` keeps prompts and model responses out of telemetry while retaining operational attributes such as model, tokens, cost, duration, status, and errors.

OpenLIT can also instrument supported frameworks and provider SDKs without changing the Collector configuration. See the [OpenLIT integrations documentation](https://docs.openlit.io/latest/sdk/integrations/overview) for the current list.

</Step>
<Step>

### Generate and verify telemetry

Run the application and allow a few seconds for the SDK and Collector batch processors to flush.

In Parseable, verify that:

1. `openlit-traces` appears in the Traces view.
2. `openlit-metrics` appears in the Metrics view.
3. A trace contains `service.name`, `gen_ai.request.model`, token usage, duration, and status fields.

For a short-lived smoke test, reduce the metric export interval so metrics flush before the process exits:

```bash
export OTEL_METRIC_EXPORT_INTERVAL=1000
python app.py
```

The interval is in milliseconds. Use the default or a longer interval for normal production workloads.

</Step>
</Steps>

## What you get in Parseable

The trace dataset contains one or more spans for each instrumented model operation. Common fields include:

| Field | Meaning |
| --- | --- |
| `service.name` | Application or service configured in `openlit.init()` |
| `deployment.environment` | Deployment environment |
| `gen_ai.operation.name` | GenAI operation, such as `chat` |
| `gen_ai.provider.name` | Model provider |
| `gen_ai.request.model` | Model requested by the application |
| `gen_ai.response.model` | Model returned by the provider |
| `gen_ai.usage.input_tokens` | Input token count |
| `gen_ai.usage.output_tokens` | Output token count |
| `gen_ai.usage.cost` | Computed request cost |
| `gen_ai.server.time_to_first_token` | Streaming time to first token |
| `span_duration_ns` | End-to-end span duration |
| `span_status_code` | Operation status |

OpenLIT emits OpenTelemetry histogram metrics including:

| Metric | Description |
| --- | --- |
| `gen_ai.client.operation.duration` | Client operation duration |
| `gen_ai.server.request.duration` | Provider request duration |
| `gen_ai.client.token.usage` | Input and output token usage |
| `gen_ai.usage.cost` | Request cost |
| `gen_ai.server.time_to_first_token` | Streaming time to first token |
| `gen_ai.server.time_per_output_token` | Average time per streamed output token |

## Query OpenLIT telemetry

Requests and token usage by model:

```sql
SELECT
  "gen_ai.request.model" AS model,
  COUNT(*) AS spans,
  SUM(CAST("gen_ai.usage.input_tokens" AS BIGINT)) AS input_tokens,
  SUM(CAST("gen_ai.usage.output_tokens" AS BIGINT)) AS output_tokens
FROM "openlit-traces"
WHERE p_timestamp > NOW() - INTERVAL '24 hours'
GROUP BY model
ORDER BY spans DESC;
```

Available metric instruments and observation counts:

```sql
SELECT
  metric_name,
  metric_type,
  COUNT(*) AS records,
  SUM(data_point_count) AS observations
FROM "openlit-metrics"
WHERE p_timestamp > NOW() - INTERVAL '24 hours'
GROUP BY metric_name, metric_type
ORDER BY metric_name;
```

Average operation duration from histogram totals:

```sql
SELECT
  "gen_ai.request.model" AS model,
  SUM(data_point_sum) / NULLIF(SUM(data_point_count), 0) AS average_seconds
FROM "openlit-metrics"
WHERE metric_name = 'gen_ai.client.operation.duration'
  AND p_timestamp > NOW() - INTERVAL '24 hours'
GROUP BY model
ORDER BY average_seconds DESC;
```

## Work with histogram metrics

Parseable stores OTLP histograms as flattened records. Use these fields:

| Field | Meaning |
| --- | --- |
| `data_point_count` | Number of observations |
| `data_point_sum` | Sum of observed values |
| `data_point_min` | Minimum observed value |
| `data_point_max` | Maximum observed value |
| `data_point_bucket_counts` | Observation counts for each histogram bucket |
| `data_point_explicit_bounds` | Upper bounds corresponding to the buckets |

If a histogram card shows **No data** while `bucket` is selected, choose `count`, `sum`, `min`, or `max`, or query the fields above with SQL. Bucket counts and bounds are stored as paired arrays rather than a single scalar `bucket` field.

## Troubleshoot

### Datasets do not appear

Check the Collector logs for authentication, endpoint, or export errors:

```bash
otelcol-contrib --config otel-collector-config.yaml
```

Confirm that the application sends OTLP/HTTP to the Collector's port `4318` and that `PARSEABLE_URL` is the Parseable base URL.

### Traces appear but metrics are empty

Metrics use a periodic exporter. Keep the application running long enough for the first export, or temporarily set `OTEL_METRIC_EXPORT_INTERVAL=1000` during a smoke test.

### Prompt or response content appears in traces

Set `capture_message_content=False` in `openlit.init()`. Review existing records separately because changing this setting only affects newly generated telemetry.

### Collector receives `404` responses

Use separate exporters with the correct `X-P-Log-Source` values. Do not append `/v1/traces` or `/v1/metrics` when using the base `endpoint` setting shown in this guide; the `otlphttp` exporter adds the signal path.
