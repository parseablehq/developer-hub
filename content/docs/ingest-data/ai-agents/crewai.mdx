[CrewAI](https://www.crewai.com/) applications can send distributed traces to Parseable through [OpenInference](https://github.com/Arize-ai/openinference) and OpenTelemetry. A single crew run becomes one trace containing the crew, agent, task, tool, and model-call spans needed to debug latency, errors, token usage, and execution flow.

## Architecture

```text
CrewAI application
  | OpenInference instrumentation
  v
OpenTelemetry SDK
  | OTLP/HTTP
  v
Parseable /v1/traces
```

This guide instruments both CrewAI and the OpenAI client. CrewAI instrumentation captures the multi-agent workflow; OpenAI instrumentation adds provider-level LLM spans and token attributes.

## Prerequisites

- A running Parseable instance and an API key with ingest access
- Python 3.10 or later
- A CrewAI application using CrewAI 1.10.1 or later
- An OpenAI API key for this example

## Set up CrewAI with Parseable

<Steps>
<Step>

### Create the Parseable traces dataset

Set the Parseable connection values:

```bash
export PARSEABLE_URL="https://<your-parseable-host>"
export PARSEABLE_API_KEY="<your-parseable-api-key>"
```

Create a dataset for CrewAI spans and tag it for Agent Observability:

```bash
curl -X PUT "$PARSEABLE_URL/api/v1/logstream/crewai-traces" \
  -H "X-API-Key: ${PARSEABLE_API_KEY}" \
  -H "X-P-Log-Source: otel-traces" \
  -H "X-P-Telemetry-Type: traces" \
  -H "X-P-Dataset-Tag: agent-observability"
```

The dataset appears in the Traces and Agent Observability views.

</Step>
<Step>

### Install the dependencies

```bash
pip install \
  crewai \
  openinference-instrumentation-crewai \
  openinference-instrumentation-openai \
  opentelemetry-sdk \
  opentelemetry-exporter-otlp-proto-http
```

</Step>

### Configure the environment

```bash
export OPENAI_API_KEY="<your-openai-api-key>"

```

Keep `PARSEABLE_URL` and `PARSEABLE_API_KEY` from step 1 in the same shell. `PARSEABLE_URL` is the base URL of the Parseable server; the exporter appends `/v1/traces` to it.

</Step>

### Instrument and run CrewAI

Configure tracing before constructing or running the crew:

```python
import os

from crewai import Agent, Crew, Process, Task
from openinference.instrumentation.crewai import CrewAIInstrumentor
from openinference.instrumentation.openai import OpenAIInstrumentor
from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk.resources import Resource
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor


parseable_url = os.environ["PARSEABLE_URL"].rstrip("/")

provider = TracerProvider(
    resource=Resource.create(
        {
            "service.name": "crewai-research-crew",
            "deployment.environment.name": "development",
        }
    )
)
provider.add_span_processor(
    BatchSpanProcessor(
        OTLPSpanExporter(
            endpoint=f"{parseable_url}/v1/traces",
            headers={
                "X-API-Key": os.environ["PARSEABLE_API_KEY"],
                "X-P-Stream": os.getenv("PARSEABLE_STREAM", "crewai-traces"),
                "X-P-Log-Source": "otel-traces",
            },
        )
    )
)

# Capture crew, agent, task, and tool spans.
CrewAIInstrumentor().instrument(tracer_provider=provider)

# Capture the underlying OpenAI calls and token usage.
OpenAIInstrumentor().instrument(tracer_provider=provider)

researcher = Agent(
    role="Researcher",
    goal="Find accurate facts about {topic}",
    backstory="You verify claims and summarize the strongest evidence.",
    llm="gpt-4o-mini",
    verbose=True,
)

writer = Agent(
    role="Writer",
    goal="Turn research about {topic} into a concise briefing",
    backstory="You write clear technical summaries for engineering teams.",
    llm="gpt-4o-mini",
    verbose=True,
)

research_task = Task(
    description="Research three important facts about {topic}.",
    expected_output="Three verified facts with short explanations.",
    agent=researcher,
)

writing_task = Task(
    description="Use the research to write a five-paragraph briefing about {topic}.",
    expected_output="A concise five-paragraph technical briefing.",
    agent=writer,
    context=[research_task],
)

crew = Crew(
    agents=[researcher, writer],
    tasks=[research_task, writing_task],
    process=Process.sequential,
    verbose=True,
)

try:
    result = crew.kickoff(inputs={"topic": "OpenTelemetry for AI agents"})
    print(result.raw)
finally:
    # Flush spans before a short-lived process exits.
    provider.shutdown()
```

Pass the provider directly to both instrumentors. Do not call `set_tracer_provider()` in a CrewAI application: CrewAI may already have installed a global provider, and OpenTelemetry permits the global provider to be set only once.

#### Expected trace structure

One `crew.kickoff()` normally produces a trace with multiple related spans:

```text
Crew execution
├── Agent and task execution
│   └── OpenAI LLM call
└── Agent and task execution
    └── OpenAI LLM call
```

Crews that use tools, delegation, retries, or additional model calls produce more child spans in the same trace. Depending on the operation, OpenInference records attributes such as the span kind, model name, token counts, inputs, outputs, agent role, task description, and errors.

</Step>
<Step>

### Verify traces and install the dashboard

Run the application at least once, then:

1. Open **Traces** in the Parseable console.
2. Select the `crewai-traces` dataset.
3. Filter by the service name `crewai-research-crew`.
4. Open a trace to inspect its span waterfall and attributes.

If the application is long-running, `BatchSpanProcessor` exports spans in the background. For scripts and jobs, keep `provider.shutdown()` so the final batch is flushed before the process exits.

#### Import the CrewAI dashboard

The [CrewAI Observability dashboard template](https://github.com/parseablehq/dashboards/tree/main/crewai-observability) provides views for:

- Run volume, success rate, errors, and latency
- Crew, agent, and task performance
- LLM calls, models, and token consumption
- Tool usage and failures
- Trace-level error investigation

Download the [dashboard JSON](https://raw.githubusercontent.com/parseablehq/dashboards/main/crewai-observability/crewai-observability-sql.json), import it from the Parseable Dashboards page, and select `crewai-traces` when prompted. The template's scenario panels use optional `load_test.*` attributes; the core panels work with the instrumentation shown above.

## Production deployment

Direct export keeps the first setup small. For production workloads, you can send OTLP from the application to an OpenTelemetry Collector and configure its `otlphttp` exporter with the same Parseable URL and headers. A collector provides centralized batching, retries, filtering, sampling, and redaction without changing the CrewAI application.

Do not enable both code-based instrumentation and OpenTelemetry no-code auto-instrumentation for the same libraries. Doing so can create duplicate spans.

## Protect sensitive data

Agent goals, backstories, task descriptions, prompts, completions, and tool inputs or outputs can contain sensitive information. Review the captured attributes before enabling tracing in production, restrict access to the traces dataset, and use OpenTelemetry processors or OpenInference configuration to redact or suppress content where required.

## Troubleshooting

### No traces appear

- Confirm that `PARSEABLE_URL` is reachable from the application.
- Confirm that the API key can ingest into the value of `PARSEABLE_STREAM`.
- Verify that the endpoint ends in `/v1/traces` and `X-P-Log-Source` is `otel-traces`.
- Keep `provider.shutdown()` at application exit so buffered spans are exported.

### LLM spans are missing

CrewAI instrumentation captures the workflow, but provider instrumentation captures the detailed OpenAI call. Ensure `OpenAIInstrumentor().instrument(tracer_provider=provider)` runs before the crew executes. Instrument the corresponding provider client if your crew uses a provider other than OpenAI.

### Spans are duplicated

Use only one instrumentation path for each library. Disable no-code auto-instrumentation when using the explicit instrumentor calls in this guide.

### CrewAI says tracing is disabled

CrewAI's tracing message refers to CrewAI's own tracing product. It does not indicate whether OpenInference is exporting OpenTelemetry spans to Parseable.
