---
title: Daytona
description: Send Daytona SDK traces and sandbox telemetry to Parseable over OTLP HTTP
---

[Daytona](https://www.daytona.io/) exposes two OpenTelemetry export paths. The SDK can export client-side operation traces, while Daytona's organization-level telemetry configuration exports telemetry generated by managed sandboxes. Both paths can send OTLP HTTP directly to Parseable.

## Understand the two export paths

| Path | Configured at | What it exports | Scope |
| --- | --- | --- | --- |
| Daytona SDK tracing | Environment of the application using the Daytona SDK | Traces for sandbox lifecycle, code execution, filesystem, process, and Daytona API operations | Operations performed by that SDK client |
| Sandbox telemetry | **Daytona Dashboard → Settings → OpenTelemetry** | Sandbox logs, sandbox traces, sandbox resource metrics, and organization resource metrics | All sandboxes in the Daytona organization |

These trace sources describe different sides of a sandbox run:

- **SDK traces** show the client request to create, use, and delete a sandbox.
- **Sandbox traces** show HTTP requests and custom spans generated inside the sandbox runtime.

SDK tracing does not export sandbox stdout/stderr or resource metrics.

## Requirements

- A [Daytona account](https://app.daytona.io/)
- A [Daytona API key](https://app.daytona.io/dashboard/keys)
- Python 3 and the `daytona` package
- A Parseable instance reachable from the SDK client for traces and from Daytona Cloud for sandbox telemetry
- Parseable credentials with permission to ingest into the selected datasets

## Install the Daytona SDK

Create and activate a virtual environment, then install the SDK:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install daytona
```

## Configure direct OTLP trace export

Generate the value for Parseable Basic authentication:

```bash
printf '%s' 'PARSEABLE_USERNAME:PARSEABLE_PASSWORD' | base64
```

Set the Daytona and OpenTelemetry environment variables:

```bash
export DAYTONA_API_KEY='<daytona-api-key>'
export DAYTONA_OTEL_ENABLED=true
export OTEL_EXPORTER_OTLP_ENDPOINT='https://parseable.example.com'
export OTEL_EXPORTER_OTLP_PROTOCOL='http/protobuf'
export OTEL_EXPORTER_OTLP_HEADERS='Authorization=Basic <base64-user-password>,X-P-Stream=daytona-traces,X-P-Log-Source=otel-traces'
```

Use the Parseable base URL without `/v1/traces`. The OTLP HTTP exporter appends the signal path automatically.

<Callout type="warn">
  Quote `OTEL_EXPORTER_OTLP_HEADERS`. Its value contains spaces; an unquoted value can cause errors such as `command not found` when sourced from a shell file. Keep API keys and Parseable credentials out of source control.
</Callout>

## Run a traced sandbox operation

Create `test_daytona.py`:

```python
import asyncio
import os

from daytona import AsyncDaytona, DaytonaConfig


async def main() -> None:
    config = DaytonaConfig(
        api_key=os.environ["DAYTONA_API_KEY"],
        otel_enabled=True,
    )

    async with AsyncDaytona(config) as daytona:
        sandbox = await daytona.create()
        try:
            result = await sandbox.process.code_run(
                'print("sandbox stdout test")'
            )
            print(result.result)
        finally:
            await daytona.delete(sandbox)


if __name__ == "__main__":
    asyncio.run(main())
```

Run it:

```bash
python test_daytona.py
```

The `async with` block closes the Daytona client and flushes pending traces. The `finally` block deletes the temporary sandbox even when code execution fails.

## Validate SDK traces in Parseable

Open the `daytona-traces` dataset in Parseable after the script completes. The exported trace data covers Daytona SDK operations such as:

- Sandbox creation, start, stop, and deletion
- Code and process execution
- Filesystem operations
- HTTP requests made by the Daytona SDK

The exact spans depend on the SDK operations executed by the application.

The `sandbox stdout test` line appears in the local process output. It is not an OTLP log record produced by this trace-only configuration.

## Export complete sandbox telemetry

Sandbox telemetry originates in Daytona's managed infrastructure. Daytona sends logs, traces, and metrics to one organization-level OTLP endpoint:

```text
Daytona
  └── OpenTelemetry Collector
        ├── logs    → Parseable dataset: daytona-logs
        ├── traces  → Parseable dataset: daytona-traces
        └── metrics → Parseable dataset: daytona-metrics
```

Use an OpenTelemetry Collector to route each signal to a separate Parseable dataset with the required signal-specific headers.

### Configure the collector

Create `otel-collector-config.yaml`:

```yaml
receivers:
  otlp:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
      http:
        endpoint: 0.0.0.0:4318

processors:
  memory_limiter:
    check_interval: 1s
    limit_mib: 256
  batch:
    timeout: 5s

exporters:
  otlphttp/daytona-logs:
    endpoint: "${env:PARSEABLE_ENDPOINT}"
    encoding: json
    headers:
      Authorization: "Basic ${env:PARSEABLE_BASIC_AUTH}"
      X-P-Stream: daytona-logs
      X-P-Log-Source: otel-logs

  otlphttp/daytona-traces:
    endpoint: "${env:PARSEABLE_ENDPOINT}"
    encoding: json
    headers:
      Authorization: "Basic ${env:PARSEABLE_BASIC_AUTH}"
      X-P-Stream: daytona-traces
      X-P-Log-Source: otel-traces

  otlphttp/daytona-metrics:
    endpoint: "${env:PARSEABLE_ENDPOINT}"
    encoding: json
    headers:
      Authorization: "Basic ${env:PARSEABLE_BASIC_AUTH}"
      X-P-Stream: daytona-metrics
      X-P-Log-Source: otel-metrics

service:
  pipelines:
    logs:
      receivers: [otlp]
      processors: [memory_limiter, batch]
      exporters: [otlphttp/daytona-logs]
    traces:
      receivers: [otlp]
      processors: [memory_limiter, batch]
      exporters: [otlphttp/daytona-traces]
    metrics:
      receivers: [otlp]
      processors: [memory_limiter, batch]
      exporters: [otlphttp/daytona-metrics]
```

Set collector environment variables without committing credentials:

```bash
export PARSEABLE_ENDPOINT='https://parseable.example.com'
export PARSEABLE_BASIC_AUTH="$(printf '%s' 'PARSEABLE_USERNAME:PARSEABLE_PASSWORD' | base64)"
```

Run the collector using the contrib distribution:

```bash
docker run --rm \
  -p 4317:4317 \
  -p 4318:4318 \
  -e PARSEABLE_ENDPOINT \
  -e PARSEABLE_BASIC_AUTH \
  -v "$PWD/otel-collector-config.yaml:/etc/otelcol-contrib/config.yaml:ro" \
  otel/opentelemetry-collector-contrib:latest
```

Expose the collector as a publicly reachable HTTPS base URL, for example `https://otel.example.com`. Protect the endpoint with authentication at a reverse proxy, ingress, or load balancer. Do not expose an unauthenticated OTLP receiver to the internet.

### Configure Daytona

Open **Daytona Dashboard → Settings → OpenTelemetry**. This is an organization-owner setting and can take up to five minutes to apply.

Enter the collector base URL without an OTLP signal path:

```text
OTLP Endpoint: https://otel.example.com
```

Add the authentication header required by the collector's HTTPS proxy, for example:

```text
Authorization: Bearer <collector-ingest-token>
```

Daytona documents `/v1/logs`, `/v1/traces`, and `/v1/metrics` export to this endpoint. The collector identifies each received OTLP signal and applies the corresponding Parseable dataset and source headers.

### What Daytona exports

Sandbox telemetry includes:

- Application stdout/stderr, system logs, runtime errors, and warnings
- HTTP request traces and custom spans emitted inside sandboxes
- Sandbox CPU, memory, and filesystem metrics
- Organization CPU, RAM, and storage usage and quota metrics, pushed every 60 seconds

<Callout type="warn">
  In validation with Daytona Python SDK `0.197.0`, sandbox traces and metrics reached the collector, but sandbox logs did not. Daytona's entrypoint log API returned the expected stdout and stderr, confirming that Daytona captured the logs, while collector diagnostics showed no incoming OTLP log records. A synthetic OTLP log sent through the same collector logs pipeline reached the `daytona-logs` dataset in Parseable, proving the collector-to-Parseable path was healthy. This isolates the missing signal upstream of the collector, likely in Daytona's organization log export or its account, region, or version availability. Treat it as a likely Daytona-side export issue rather than a universally confirmed product bug.
</Callout>

Daytona exports per-sandbox metrics including:

- `daytona.sandbox.cpu.utilization` and `daytona.sandbox.cpu.limit`
- `daytona.sandbox.memory.utilization`, `daytona.sandbox.memory.usage`, and `daytona.sandbox.memory.limit`
- `daytona.sandbox.filesystem.utilization`, usage, available space, and total space

### Generate a telemetry workload

SDK tracing is not required for this test. Keep a sandbox active long enough for Daytona to collect multiple samples:

```python
import asyncio
import os

from daytona import AsyncDaytona, DaytonaConfig


async def main() -> None:
    config = DaytonaConfig(
        api_key=os.environ["DAYTONA_API_KEY"],
        otel_enabled=False,
    )

    async with AsyncDaytona(config) as daytona:
        sandbox = await daytona.create()
        try:
            result = await sandbox.process.code_run(
                """
import time

data = bytearray(200 * 1024 * 1024)
end = time.time() + 120

while time.time() < end:
    sum(i * i for i in range(500000))

print("Daytona metrics workload complete")
""",
                timeout=180,
            )
            print(result.result)
        finally:
            await daytona.delete(sandbox)


if __name__ == "__main__":
    asyncio.run(main())
```

After the workload starts, wait at least 60–90 seconds. Validate:

- `daytona-traces` contains sandbox HTTP requests or custom spans when the workload emits them.
- `daytona-metrics` contains resource metrics beginning with `daytona.sandbox.`.
- `daytona-logs` contains sandbox stdout/stderr only if Daytona delivers OTLP log records for the sandbox and platform version in use.

The collector route is independent from SDK tracing. SDK traces can continue exporting directly to Parseable, or their `OTEL_EXPORTER_OTLP_ENDPOINT` can point to the same collector when one trace route is preferred.

<Callout type="info">
  A direct Daytona-to-Parseable configuration can target one signal by setting one `X-P-Log-Source` and one `X-P-Stream`. It cannot cleanly route all three signals because Daytona applies one shared header set. The collector configuration above provides correct routing for every signal Daytona delivers.
</Callout>

## Troubleshooting

- **No records appear** — Confirm `DAYTONA_OTEL_ENABLED=true`, use `http/protobuf`, and close the Daytona client so buffered spans flush.
- **Request reaches the wrong path** — Set `OTEL_EXPORTER_OTLP_ENDPOINT` to the Parseable base URL. Do not append `/v1/traces`.
- **Authentication fails** — Regenerate the Base64 value from the exact Parseable username and password, then keep the `Authorization=Basic ` prefix.
- **Trace data reaches the wrong dataset** — Set `X-P-Stream=daytona-traces` and `X-P-Log-Source=otel-traces`.
- **Shell reports `command not found` while sourcing variables** — Wrap the complete `OTEL_EXPORTER_OTLP_HEADERS` value in single quotes.
- **Sandbox logs or metrics are missing from the SDK trace flow** — Expected. Configure Daytona organization sandbox telemetry separately when those signals are required.
- **No sandbox telemetry appears** — Confirm the organization setting has had five minutes to apply and the collector is publicly reachable over HTTPS.
- **Only one signal appears** — Confirm all three collector pipelines are present and each exporter uses the matching `X-P-Log-Source`.
- **Daytona captures logs but `daytona-logs` remains absent** — Enable a collector `debug` exporter on the logs pipeline and send a synthetic OTLP log through the same receiver. If the synthetic log reaches Parseable while Daytona's entrypoint log API contains stdout/stderr and the collector receives no Daytona `LogRecord`, the missing signal is upstream of the collector. Report it to Daytona with the account, region, and SDK/platform version.
- **Collector receives data but Parseable is empty** — Check collector logs for authentication, endpoint, and exporter errors.
- **Organization metrics are delayed** — Daytona pushes them every 60 seconds; allow additional time after saving the organization configuration.

See [Daytona OpenTelemetry collection](https://www.daytona.io/docs/en/observability/otel-collection/), [Parseable OTLP trace ingestion](/docs/ingest-data/otel/traces), and [Parseable OTLP metrics ingestion](/docs/ingest-data/otel/metrics) for protocol details.
