---
title: GitHub Copilot
description: Send GitHub Copilot agent traces and metrics to Parseable through OpenTelemetry
---

GitHub Copilot CLI can export OpenTelemetry traces and metrics for agent sessions. Traces connect an `invoke_agent` root span with model calls and tool executions, while metrics report token usage and other numeric signals.

This guide sends both signals through an OpenTelemetry Collector. Parseable-specific authentication and dataset headers stay in the Collector configuration.

```text
GitHub Copilot CLI
  | OTLP/HTTP
  v
OpenTelemetry Collector
  |-- traces ---> copilot-traces
  +-- metrics --> copilot-metrics
```

GitHub documents the emitted spans, attributes, metrics, and supported environment variables in the [Copilot CLI command reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#opentelemetry-monitoring).

## Prerequisites

You need:

- GitHub Copilot CLI installed and authenticated
- An OpenTelemetry Collector Contrib instance reachable from Copilot CLI
- A Parseable instance reachable from the Collector
- A Parseable API key with ingest access

## Configure the Collector

Create `otel-collector.yaml`:

```yaml
receivers:
  otlp:
    protocols:
      http:
        endpoint: 0.0.0.0:4318

processors:
  batch:

exporters:
  otlphttp/copilot_traces:
    traces_endpoint: ${env:PARSEABLE_URL}/v1/traces
    encoding: json
    headers:
      X-P-API-Key: ${env:PARSEABLE_API_KEY}
      X-P-Stream: copilot-traces
      X-P-Log-Source: otel-traces

  otlphttp/copilot_metrics:
    metrics_endpoint: ${env:PARSEABLE_URL}/v1/metrics
    encoding: json
    headers:
      X-P-API-Key: ${env:PARSEABLE_API_KEY}
      X-P-Stream: copilot-metrics
      X-P-Log-Source: otel-metrics

service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [batch]
      exporters: [otlphttp/copilot_traces]
    metrics:
      receivers: [otlp]
      processors: [batch]
      exporters: [otlphttp/copilot_metrics]
```

Start the Collector:

```bash
export PARSEABLE_URL="https://<your-parseable-host>:8000"
export PARSEABLE_API_KEY="<parseable-api-key>"

otelcol-contrib --config otel-collector.yaml
```

For a self-hosted deployment that uses basic authentication, replace `X-P-API-Key` with:

```yaml
Authorization: Basic <base64-encoded-username-and-password>
```

## Enable Copilot telemetry

Set the OTLP endpoint before starting Copilot CLI:

```bash
export COPILOT_OTEL_ENABLED=true
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
export OTEL_EXPORTER_OTLP_PROTOCOL=http/json
export OTEL_SERVICE_NAME=github-copilot

copilot
```

Setting `OTEL_EXPORTER_OTLP_ENDPOINT` also enables telemetry, but `COPILOT_OTEL_ENABLED=true` makes the intent explicit. Do not append `/v1/traces` or `/v1/metrics`; Copilot CLI adds the signal path.

Copilot CLI supports `http/json` and `http/protobuf`. The Collector configuration above accepts either protocol over OTLP/HTTP.

## Verify ingestion

Start Copilot CLI and submit a request that causes one model call and one tool call. In Parseable:

1. Open `copilot-traces` in the Traces view.
2. Find an `invoke_agent GitHub Copilot Chat` root span.
3. Open the trace and confirm it contains `chat` and `execute_tool` child spans.
4. Check `copilot-metrics` for token usage metrics.

Useful trace fields include:

- `span_trace_id`, `span_span_id`, and `span_parent_span_id`
- `span_name`, `span_duration_ns`, and `span_status_code`
- `gen_ai.request.model` and `gen_ai.response.model`
- `gen_ai.usage.input_tokens` and `gen_ai.usage.output_tokens`
- `gen_ai.tool.name`
- `github.copilot.git.repository` and `github.copilot.git.branch`

## Import the dashboard

Download the [GitHub Copilot Observability dashboard](https://github.com/parseablehq/dashboards/tree/main/github-copilot-observability) and import its JSON file in Parseable. Map **Traces Dataset** to `copilot-traces`.

The dashboard covers trace volume, sessions, model and token usage, tools, latency, errors, repositories, and recent traces.

## Configure the Copilot SDK

Applications built with the Copilot SDK can enable the same CLI telemetry through `TelemetryConfig`. For TypeScript:

```typescript
import { CopilotClient } from "@github/copilot-sdk";

const client = new CopilotClient({
  telemetry: {
    otlpEndpoint: "http://localhost:4318",
    otlpProtocol: "http/json",
    captureContent: false,
  },
});
```

GitHub provides equivalent options for Python, Go, .NET, Java, and Rust in [OpenTelemetry instrumentation for Copilot SDK](https://docs.github.com/en/copilot/how-tos/copilot-sdk/observability/opentelemetry).

## Protect sensitive content

Copilot excludes prompts, responses, and tool arguments by default. Keep content capture disabled for shared or production environments.

Setting the following variable includes full message content:

```bash
export OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true
```

Captured data can include source code, file contents, user prompts, model responses, and tool arguments. Apply Collector redaction rules and access controls before enabling it. GitHub's [OpenTelemetry agent monitoring guide](https://docs.github.com/en/copilot/concepts/agents/opentelemetry) describes the privacy behavior.

## Troubleshooting

- **No spans arrive:** confirm Copilot CLI can reach the Collector and set `OTEL_LOG_LEVEL=DEBUG` to inspect exporter diagnostics.
- **The trace has no child spans:** generate a new session after setting the environment variables; existing Copilot processes do not inherit later shell changes.
- **Parseable rejects exports:** check the Collector logs and verify the trace and metric exporters use different `X-P-Stream` and `X-P-Log-Source` values.
- **The dashboard is empty:** map **Traces Dataset** to `copilot-traces` and choose a time range that includes the test session.
